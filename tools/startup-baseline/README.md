# Изолированные замеры запуска

Инструменты для Windows/.NET 10 и 11. Они не меняют исходники приложения или его зависимости. Основной отчёт: [STARTUP_BASELINE_2026-11-24.md](../../docs/analysis/STARTUP_BASELINE_2026-11-24.md).

## Чтение коллекции и подготовка восстановления

Из корня репозитория:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/startup-baseline/Run-StorageBaseline.ps1 -Framework net10.0 -Catalog 'C:\Users\NickFeD\AppData\Local\NiTorrent\LocalState\Torrents\torrent_downloads.json'
powershell -NoProfile -ExecutionPolicy Bypass -File tools/startup-baseline/Run-StorageBaseline.ps1 -Framework net11.0 -Catalog 'C:\Users\NickFeD\AppData\Local\NiTorrent\LocalState\Torrents\torrent_downloads.json'
```

`ExecutionPolicy Bypass` действует только для нового процесса PowerShell и нужен здесь из-за запрета запуска локальных скриптов. Системная политика не изменяется. Для сравнения закрыть другие активные нагрузки и выполнять команды последовательно.

Без `-Catalog` создаются только синтетические сценарии. Существующий каталог читается в снимок; никакой экземпляр production-репозитория не создаётся над живой папкой пользователя. В проект напрямую включены текущие исходники репозитория и restore use case, без WinUI и NuGet-зависимостей. Это не сборка и не запуск всего NiTorrent.

Сценарии: пустой; 1/100 лёгких записей; одна запись с 1000 файлами и 1 МиБ источника; реальный каталог; 10/100 синтетических копий самой большой записи реального каталога. Последние не добавляются в настоящий клиент. Файлы скачиваемого содержимого не открываются. Искусственные source bytes не обязаны быть валидным `.torrent`, поскольку движок не вызывается.

Каждый сценарий по умолчанию содержит 2 прогревочных и 7 измеряемых проходов. Отдельно измеряются:

- конструктор репозитория с созданием/проверкой каталогов;
- `LoadingAsync`: чтение JSON и создание внутреннего словаря;
- `GetAllAsync`: получение моделей списка;
- `GetAllForRestoreAsync`: модели восстановления и декодирование Base64;
- `RestoreSessionUseCase` с пустым gateway: подготовка и настоящие `Task.Delay(5)`, без MonoTorrent, сети и файлов скачивания.

Последняя метрика уже включает повторный `GetAllForRestoreAsync`; складывать их как независимые фазы нельзя. `ReadAllocatedBytes` относится к чтению и обеим проекциям, исключая следующий no-op restore. Это счётчик всего процесса, не только одного async-потока.

Результаты, версии, хеши исходников и контроль неизменности входа сохраняются в новом каталоге `artifacts/startup-baseline/`. Он игнорируется Git. Там же есть копия реального каталога с исходными именами/путями: не публиковать эту папку как обезличенный отчёт. Сводный Markdown содержит только размеры и времена.

Файлы создаются непосредственно перед чтением, поэтому это повторные чтения с прогретым/неконтролируемым кэшем ОС. Здесь нет метрики cold start, первого кадра, DI, реального движка или хеширования скачанных данных. Ничего из этого нельзя выводить из времени JSON.

## Наблюдение за готовой сборкой

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/startup-baseline/Measure-InstalledStartup.ps1 -Executable 'C:\Games\NiTorrent\NiTorrent.App.exe' -ObservationSeconds 30
```

Перед запуском нужно штатно завершить предыдущий экземпляр через приложение. Скрипт отказывается запускать новый замер при существующем процессе: иначе измерялось бы перенаправление активации.

Наблюдатель запускает обычное видимое приложение с его реальным профилем. Приложение может выполнять свою обычную запись состояния и сетевую работу. Скрипт сам не меняет профиль, не закрывает и не убивает приложение; после замера оно остаётся для штатного выхода пользователем.

Записываются хеш EXE, runtimeconfig, время возврата запуска, обнаружения main window handle и input-idle, наблюдаемые CPU/working set, выход процесса. Window handle и input-idle не подтверждают первый кадр, показ коллекции или готовность runtime. `null` означает, что событие не наблюдалось, а не нулевое время.

Один прогон — отдельный образец, без заявления о медиане. Для полноценного запуска нужны runtime-маркеры/трасса и воспроизводимые наборы данных с работоспособной сборкой. Большие коллекции не нужно имитировать в реальном профиле ради этого наблюдателя.
