Дата: 2026-11-26. По запросу владельца обычное Win32-меню заменено на WinUI `MenuFlyout` с иконками команд и темой приложения. Регистрация значка через H.NotifyIcon и правила закрытия приложения сохранены.

## Реализация

`TrayService` по-прежнему владеет H.NotifyIcon.Core.TrayIcon и получает скорости из существующего runtime. `FluentTrayMenu` размещает меню в отдельном прозрачном служебном WinUI-окне, когда основное окно скрыто. Это подход SecondWindow; свойство `TaskbarIcon.ContextMenuMode` напрямую не используется, чтобы не подключать автоматическое восстановление значка из WinUI-обёртки библиотеки.

Служебное окно создаётся лениво при первом открытии меню, скрывается после закрытия меню и освобождается при уходе из трея, восстановлении значка или выходе. Оно имеет стиль tool window, без рамки, заголовка и кнопки в панели задач. Положение выбирается по координатам события значка с учётом рабочей области монитора; WinUI размещает flyout за пределами маленького окна-хоста.

Сохранены «Открыть», «Приостановить всё», «Продолжить всё», «Выход» и строка скоростей. Скорости обновляются и в открытом меню. Массовые действия остаются асинхронными; их пункты блокируются при занятости. Меню получает актуальную тему приложения при открытии. Ошибка создания/открытия меню записывается в журнал и возвращает основное окно.

Вспомогательный метод H.NotifyIcon `HideWindowInTaskbar` отклоняет допустимый нулевой extended style нового окна. Для этого узкого случая добавлен `NativeTrayWindow`: проверяет не только нулевой результат Get/SetWindowLongW, но и код ошибки. Изменяются только 32-битные флаги GWL_EXSTYLE; чужие HWND не освобождаются.

Изолированный UI helper: `artifacts/tray-comparison/ui-fluent-smoke.ps1`. Использует временный `NITORRENT_DATA_ROOT`, один синтетический торрент, отключённое сетевое обнаружение и UI Automation. Профиль торрентов пользователя не использовался.

В Debug проверены наличие пунктов именно WinUI MenuItem, работа продолжения/паузы из меню с сохранением каталога, «Открыть», повторный вход в трей, «Выход» с ExitCode=0 и Clean marker. Проверены Escape и размещение у реального значка. Образец: `artifacts/startup-baseline/ui-Debug-20261126T183848877Z/`, снимок только меню — `fluent-menu.png`.

Итоговый Release повторил этот сценарий успешно: `artifacts/startup-baseline/ui-Release-20261126T185422389Z/`, ExitCode=0, Clean marker; `fluent-menu.png` содержит снимок меню. При повторном открытии окно-хост явно показывается перед активацией.

Ограничение: дополнительный автоматический сценарий перевода фокуса на искусственное внеэкранное Win32-окно не подтвердил закрытие меню. Отдельный глобальный перехват фокуса в итоговую реализацию не включён. Подтверждены Escape и закрытие при выполнении команд; переключение между обычными приложениями и щелчок снаружи требуют ручной проверки. Не считать этот дополнительный сценарий прошедшим.

Многомониторные конфигурации с отрицательными координатами и разные DPI отдельно не прогонялись. Расширенная информационная панель не добавлялась.
