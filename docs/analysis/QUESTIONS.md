# Решения владельца и открытые вопросы

Актуализировано 2026-11-27. Согласованный объём модульного монолита — [MM-01–MM-06](MODULAR_MONOLITH_REQUIREMENTS.md), выполненный этап — [отчёт](MODULAR_MONOLITH_IMPLEMENTED_2026-11-27.md). Наличие открытого вопроса не требует остановки независимой работы и не разрешает реализацию следующего этапа.

| ID | Состояние |
| --- | --- |
| Q-01 | Приоритеты подтверждены: запуск/завершение, понятные модули, будущие окна. Первый этап монолита завершён, следующий не выбран |
| Q-02 | Ранние Start/Pause принимаются и сохраняются; применяется актуальное намерение |
| Q-03 | Ошибка одной записи изолируется; Retry готовит эту запись. Отдельное восстановление через новый источник с предпросмотром ещё не реализовано |
| Q-04 | Подтверждённое добавление может сохраниться до готовности engine и затем подготавливаться сессией; сценарий проверен. По последующему согласованию 27 ноября окно предпросмотра открывается перед metadata, показывает ожидание, ошибку/повтор и отменяет запрос при закрытии; проверки модели окна см. CURRENT_CODE. Библиотечный кэш и реальный сетевой UI-сценарий этим проходом не подтверждены |
| Q-05 | Раздача может продолжаться после получения файлов; Start/Pause допустимы для живых записей. Отдельный новый пользовательский статус «Завершён» не добавлялся |
| Q-06 | Оба режима удаления реализованы. Удаление с данными сохраняет Deleted/DeleteFiles до успеха и переживает перезапуск |
| Q-07 | Расширенный экран деталей/пиры/трекеры отложены; выбрать состав следующего этапа |
| Q-08 | Закрыто: ExitApplication, MinimizeToTray, AskUser с диалогом и запоминанием выбора |
| Q-09 | Открыто: UX при неуспешной записи/применении настроек, момент подтверждения Apply и необходимость отката. Сейчас автоматического отката нет |
| Q-10 | Открыто: перечень поддерживаемых старых выпусков и миграции. Текущий перенос сохранил текущий JSON; это не доказательство миграции с любого прежнего torrent_catalog.json |
| Q-11 | Текущий release workflow: unpackaged win-x64 + Inno Setup. Основная будущая политика распространения и MSIX/AOT-проверки не утверждены этим этапом |
| Q-12 | Системный magnet-протокол отдельно не согласован; наличие обработчика аргументов не доказывает регистрацию у пользователя |
| Q-13 | Есть прежние замеры хранения и изолированные UI-прогоны; сопоставимая серия запуска на типичном/большом профиле всё ещё нужна |
| Q-14 | Числовые бюджеты запуска/первого кадра не установлены. Для скорости/прогресса согласовано примерно одно обновление в секунду; настройка позже |
| Q-15 | На первом этапе одно главное окно с существующими страницами. Политика закрытия нескольких окон остаётся открытой |
| Q-16 | Остановка отменяет новую работу, ожидает принятые операции и сохраняет состояние в пределах 10 секунд. Clean marker не обещается при неполной остановке |
| Q-17 | Один активный движок, смена после перезапуска. App явно регистрирует MonoTorrent; второй адаптер не внедрён |
| Q-18 | Открыто: выбрать конкретного кандидата и сравнить возможности. Имена libtorrent/aria2/qBittorrent/Transmission — кандидаты, не подтверждённая расшифровка слов владельца |

Дополнительные согласованные решения: скрытые в трей страницы отписываются; трей сохраняет Summary; при возврате активная страница подключается заново. Потеря связи сохраняет последние значения с отметкой и автоматическим восстановлением наблюдения. Неподдерживаемое показывается недоступным с объяснением. Новая история данных не требуется.

Перед изменением объединения Paused/Stopped сверить [наблюдения](OBSERVATIONS.md) и прежний ADR-002: фактические подписи различаются. Перед будущим серверным backend определить, управляют ли им другие клиенты, кто владеет процессом и как согласуются пути/коллекция.
