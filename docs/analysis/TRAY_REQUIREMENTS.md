# ТЗ: трей и закрытие NiTorrent

Дата: 2026-11-26. Статус: согласованные с владельцем требования; выполнена реализация на H.NotifyIcon. Архитектура, проверки и ограничения — в [отчёте реализации](TRAY_IMPLEMENTED_2026-11-26.md). Предшествующее исследование — в [сравнении](TRAY_LIBRARY_COMPARISON_2026-11-26.md).

Этот документ имеет приоритет над прежним описанием резервной минимизации в панель задач в материалах lifecycle. Требования к самостоятельному ядру и штатному завершению сохраняются: [RUNTIME_LIFECYCLE_IMPLEMENTED.md](RUNTIME_LIFECYCLE_IMPLEMENTED.md), [LIFECYCLE_REQUIREMENTS.md](LIFECYCLE_REQUIREMENTS.md).

## 1. Область этапа

Один значок NiTorrent в системной области уведомлений и обычное меню команд. Пока основное окно показано, значок отсутствует. При работе в трее окно скрыто, ядро продолжает работу.

Расширенная панель возле значка, дополнительный режим интерфейса трея и запуск сразу в трее отложены. Обсуждение двух режимов не означает два одновременных значка. Экономный режим процесса не утверждён как требование.

## 2. Крестик и настройка закрытия

| Режим | Действие крестика |
| --- | --- |
| Завершить приложение | Штатно остановить приложение и сохранить состояние |
| Спрашивать | Показать диалог выбора между завершением и сворачиванием в трей |
| Свернуть в трей | Перейти в трей без вопроса о закрытии |

Режим по умолчанию — **«Спрашивать»**. Все три значения доступны в окне настроек.

Диалог выбора содержит действия «Завершить приложение», «Свернуть в трей» и возможность «Запомнить выбор». Подтверждённый выбор с этой отметкой меняет ту же настройку на соответствующий режим. Без отметки режим остаётся «Спрашивать». Закрытие диалога без выбора оставляет окно открытым и не меняет настройку.

Настройка относится к крестику основного окна. Команда «Выход» из трея всегда завершает приложение без дополнительного вопроса, независимо от настройки.

## 3. Переход в трей и ошибки

1. По запросу сворачивания создать/подготовить значок и зарегистрировать его в области уведомлений.
2. Убедиться в успехе регистрации, затем скрыть основное окно. Одного создания объекта библиотеки недостаточно.
3. Если первая попытка неудачна, выполнить ровно одну повторную попытку инициализации/регистрации.
4. Если обе попытки неудачны, оставить окно доступным и показать диалог с действиями «Завершить приложение» и «Оставить открытым».
5. Закрытие диалога без выбора оставляет приложение открытым. «Завершить приложение» использует штатное завершение.

Минимизация в панель задач после двух ошибок больше не является выбранным поведением. Ошибка трея сама по себе не завершает приложение и не останавливает ядро. Бесконечный цикл повторов недопустим.

## 4. Возвращение в окно

| Событие | Результат |
| --- | --- |
| Двойной левый клик по значку | Показать и активировать основное окно, убрать значок |
| «Открыть» в меню | То же поведение |
| Повторный запуск NiTorrent | Вернуть окно существующего экземпляра и убрать значок |
| Открытие `.torrent` или magnet извне | Вернуть окно, убрать значок и обработать активацию обычным сценарием |
| Правый клик по значку | Открыть меню, оставить приложение в трее |

Один левый клик не должен выполнять действие двойного клика. Возвращение окна не пересоздаёт ядро и не начинает восстановление коллекции заново.

## 5. Меню и скорости

Меню содержит:

- информационную строку суммарных скоростей загрузки и отдачи, примерно как в существующем меню;
- «Открыть»;
- «Приостановить всё»;
- «Продолжить всё»;
- «Выход».

Скорости должны отражать актуальную работу всей сессии, в том числе при скрытом окне. Это информация, а не исполняемая команда. Точное оформление, порядок разделителей и частота обновления ещё не утверждены.

## 6. Массовые команды

Обе команды применяются ко всей коллекции независимо от фильтра и открытой страницы. Подготовка и передача — разные процессы: пауза не означает отмену восстановления сессии.

| Состояние торрента | «Приостановить всё» | «Продолжить всё» |
| --- | --- | --- |
| Скачивание или раздача | Приостановить передачу | Продолжать работу |
| Приостановлен, в том числе вручную | Оставить на паузе | Запустить |
| Ожидает подготовки или подготавливается | Подготовку продолжить; применить паузу, не запускать передачу после подготовки | По готовности применить намерение запуска |
| Ошибка отдельного торрента | Применить намерение паузы по правилам обычной индивидуальной команды; отдельный автоматический повтор для этого случая не согласован | Повторить подготовку и применить намерение запуска |
| Удаляется, в том числе с данными | Продолжать удаление | Продолжать удаление |

«Приостановить всё» эквивалентно индивидуальному действию остановки/паузы для каждого подходящего торрента. Последующие индивидуальные команды учитываются существующими правилами актуального намерения. Ни одна массовая команда не отменяет удаление и не возвращает удаляемую запись к передаче.

Повтор ошибок через «Продолжить всё» использует обычную подготовку проблемной записи без окна повторного добавления. Эта команда не означает бесконечный повтор и не меняет ранее согласованную политику общего сбоя движка.

## 7. Перезапуск Explorer

Если значок пропал при перезапуске Explorer, восстановить его автоматически. При неудаче выполнить одну повторную попытку; после второй ошибки вернуть основное окно и показать диалог из раздела 3.

Если основное окно уже показано, перезапуск Explorer не должен создавать значок. Восстановление значка не меняет состояния торрентов и не перезапускает ядро.

## 8. Состояния пользовательского интерфейса

Это модель ожидаемого поведения, а не предписание создавать отдельный класс для каждого состояния.

| Состояние | Окно | Значок | Допустимый следующий шаг |
| --- | --- | --- | --- |
| Окно открыто | Показано | Отсутствует | Диалог выбора, переход в трей, завершение |
| Выбор закрытия | Показано с диалогом | Отсутствует | Остаться, перейти в трей, завершить |
| Переход в трей | Остаётся доступным до успешной регистрации | Создаётся | Трей либо диалог ошибки после двух неудач |
| Работа в трее | Скрыто | Зарегистрирован | Открыть окно, команды меню, завершить |
| Восстановление значка | Изначально скрыто | Восстанавливается | Трей либо показ окна и диалога ошибки |
| Ошибка трея | Показано с диалогом | Рабочего значка нет | Остаться открытым либо завершить |
| Завершение | Подчинено существующему shutdown | Убирается | Штатный выход |

## 9. Инженерные предложения для реализации

Ниже рекомендации по выполнению ТЗ, а не новые решения владельца о продукте:

- Один владелец состояния окна/трея управляет переходами; библиотека обслуживает значок, события и меню. Настройка крестика, повтор и shutdown принадлежат NiTorrent.
- Не допускать параллельных инициализаций и нескольких диалогов от повторных нажатий. При возврате окна или начале завершения отменять устаревшие попытки восстановления.
- После частичной ошибки освобождать созданные ресурсы до повторной попытки; при завершении отписать события и освободить значок, меню и служебные окна.
- При возврате сначала обеспечить доступность основного окна, затем убирать значок.
- Получать скорости из состояния самостоятельного ядра, не из подписки страницы торрентов. Не заводить второй движок или отдельный опрос движка ради трея.
- Для массовой команды обрабатывать независимые записи так, чтобы ошибка одной не мешала остальным; точную форму сообщения о частичном результате определить при реализации.
- Реакцию на `TaskbarCreated` строить по событию оболочки. Учитывать внутреннее автоматическое восстановление библиотеки, чтобы суммарно осталось две попытки, а ошибки были видимы NiTorrent.

При реализации выбрано: повтор через 500 мс; новый пользовательский запрос после «Оставить открытым» получает новую последовательность из двух попыток. По последующему запросу владельца меню переведено на Fluent MenuFlyout в служебном окне; строка скоростей и tooltip обновляются по событиям runtime, включая открытое меню. Явно сохранённые значения настройки сохраняются; отсутствующее значение получает «Спрашивать». Кнопка обычной минимизации не переводит приложение в трей. Взаимодействие с отдельным окном предпросмотра не менялось и требует отдельной проверки.

Матрица требуемых проверок. Фактически выполненные проверки и их ограничения перечислены в отчёте реализации.

| ID | Что проверить |

| T03 | Пока окно показано, значка нет; в трее окно скрыто, передача продолжается |

## 11. Исходные расхождения до реализации

Проверено статически 2026-11-26:

- `AppSettings.CloseBehavior` без явного значения получает `ExitApplication=0`, а не новый default «Спрашивать».
- `TorrentSettingsViewModel` и страница настроек используют переключатель двух режимов. `AskUser` в `MainWindowLifecycle` сейчас запрашивает завершение без диалога.
- `HideToTrayAsync` скрывает окно до `SetVisible(true)`; при ошибке инициализации выполняет минимизацию. `_trayUnavailable` запрещает последующие попытки.
- `TrayService` открывает окно по `Selected`, а не по согласованному двойному клику; массовых команд нет, обновление скоростей закомментировано.

Эти расхождения устранены в реализации на H.NotifyIcon; список сохранён как контекст исходной задачи.
