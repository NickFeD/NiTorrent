## Наблюдение

Summary обслуживает общие скорости без полного построения списка. Collection и Torrent дают состояния коллекции или конкретного Id. Peers/Trackers пока возвращают Unsupported с объяснением. Waiting, Connected, Disconnected и Unsupported различаются; нулевые значения не означают отсутствие поддержки.

Новый потребитель получает последнее доступное состояние и дальнейшие обновления. Один сборщик обслуживает общий спрос. Обработчик каждого потребителя вызывается последовательно; ожидающий буфер хранит только последний снимок. После Dispose дополнительный сбор прекращается, если потребителей больше нет; уже начатая операция может завершиться. Потребитель должен соблюдать токен отмены.

При ошибке сохраняются последние значения и отметка потери связи. Пока есть спрос, чтение повторяется автоматически; команды с побочными эффектами этим механизмом не повторяются.

## Запись и жизненный цикл

Start/Pause сохраняют актуальное намерение через сессию. Удаление с данными остаётся в каталоге до успеха; удаление без данных не требует запуска передачи. Готовность host не означает окончания восстановления коллекции.

Чтение/редактирование настроек не должно менять живое состояние по ссылке. При этом текущая запись и применение не образуют транзакцию: новые настройки могут оставаться в памяти после ошибки записи; автоматический откат не обещается. См. [наблюдения](../analysis/OBSERVATIONS.md).

ITorrentSession, runtime gateway и repository — внутренние интерфейсы реализации по отношению к Desktop; они не становятся интерфейсом UI от того, что C#-тип public для других внутренних сборок.

Прежние ITorrentWorkflowService/ITorrentCommandService/ITorrentWriteService не являются текущим командным путём. Старый документ сохранён в [архиве](archive/APPLICATION_CONTRACTS_2026-04-06.md).
