# Требования к отзывчивости и надёжности

Актуализировано 2026-11-27. Числовые бюджеты первого кадра, запуска на больших коллекциях и сетевой производительности владельцем пока не установлены.

- Подготовка runtime не должна определять время жизни окон; ранние команды сохраняют намерение и применяются сессией.
- Передача и обязательная работа ядра продолжаются без UI. Дополнительный сбор для отображения зависит от спроса.
- Для скорости/прогресса согласован ориентир около одного обновления в секунду. Это не гарантия ответа внешнего сервера за секунду; пользовательская настройка отложена.
- Медленный потребитель не задерживает остальных и не создаёт очередь истории; отмена/освобождение подписок обязательны.
- Ошибка одной записи изолируется, удаление с данными сохраняется до успеха, финальное сохранение не должно создавать ложный clean marker.
- Срок штатного завершения host ограничен 10 секундами; по истечении этого срока нельзя обещать полную остановку и сохранение.
- Трей использует общий источник и не ухудшает работу страницы вторым engine/polling.

Проверки: [архитектурные и lifecycle-тесты](../analysis/MODULAR_MONOLITH_IMPLEMENTED_2026-11-27.md), изолированные UI-сценарии и отдельные воспроизводимые измерения для производительности. Сам перенос в модули не доказывает ускорения.

Прежние общие цели — [исторический документ](archive/NFR_SLO_2026-04-05.md); они не заменяют реальные результаты. Расхождения Paused/Stopped и ошибки Apply записаны в [OBSERVATIONS](../analysis/OBSERVATIONS.md), а не объявлены автоматически устранёнными.
