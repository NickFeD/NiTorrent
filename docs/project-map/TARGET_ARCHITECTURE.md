# Принятая архитектура и направление развития

Актуализировано 2026-11-27. Принятый и реализованный первый этап — [ТЗ модульного монолита](../analysis/MODULAR_MONOLITH_REQUIREMENTS.md), состояние — [отчёт](../analysis/MODULAR_MONOLITH_IMPLEMENTED_2026-11-27.md).

## Обязательные правила первого этапа

- Torrents владеет коллекцией, намерениями, подготовкой, передачей, удалением, хранением и настройками движка.
- Desktop владеет окнами, страницами, треем, темой, активациями и локальным состоянием отображения.
- Updates предоставляет свой интерфейс; App собирает модули, явно выбирает адаптер и согласует завершение.
- UI обращается через Contracts; типы движка, репозиторий и живой TorrentDownload не выдаются потребителям.
- Сессия не зависит от окон. Наблюдение включается по спросу; последняя отписка прекращает дополнительный сбор для UI, сохраняя работу ядра.
- Скорость/прогресс обновляются примерно раз в секунду; медленный потребитель получает последний ожидающий снимок без очереди истории.
- При скрытии в трей страницы отписываются; трей наблюдает Summary. Возврат подключает активную страницу заново.
- Граф зависимостей и фактические ссылки сборок проверяются архитектурными тестами и ограничениями проектов/internal.

Несколько окон, второй адаптер, расширенные сведения и настройка частоты отложены. Для будущего выбора подтверждён один движок на приложение со сменой после перезапуска. Конкретные сервер/библиотека не выбраны. Перенос в модули не является доказательством ускорения запуска.
