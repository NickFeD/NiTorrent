# Проверки после изменений

Обновлено 2026-11-27. Это список проверок будущего изменения, а не заявление, что каждый сценарий выполнен заново при редактировании документации.

## Автоматические проверки

- Собрать актуальное решение и выполнить относящиеся к изменению тесты по командам [отчёта](../analysis/MODULAR_MONOLITH_IMPLEMENTED_2026-11-27.md).
- Проверить архитектурный граф, фактические зависимости сборок, отсутствие утечек типов движка и анализ всех проектов.
- Для подписок: первый/последний потребитель, несколько областей/Id, медленный и ошибочный обработчик, отсутствие очереди истории, отмена и восстановление связи.
- Для UI-наблюдения: скрытие в трей/возврат, сохранение выбора, повторные циклы без дублирования.
- Для команд: раннее намерение, гонка с восстановлением, оба режима удаления, локальная ошибка/Retry, сохранение при выходе.
- Для хранения: старый текущий JSON, повреждённый каталог, неудачная запись и честный clean marker.

## Изолированные UI-сценарии по затронутому объёму

- Добавление файла/magnet через preview, выбор файлов и дубликат; новая функция details отдельно не считается проверенной существованием страницы.
- Три режима X, запоминание выбора, восстановление окна, Fluent-меню, пауза/продолжение, Exit из трея.
- Ошибка регистрации значка: ограниченный повтор, доступное окно и диалог.
- Настройки: чтение/редактирование, сохранение и ошибка применения. Автоматического отката сейчас нет; не использовать старый чеклист как утверждение обратного.

Использовать отдельный NITORRENT_DATA_ROOT и подготовленные файлы. Не запускать destructive-проверки на пользовательской коллекции. Различать ошибки песочницы и реального UI; AOT/MSIX/другие платформы проверяются отдельно.
