# Архитектурные ограничения

Актуализировано 2026-11-27 по принятому первому этапу.

- Не обращаться из Desktop к repository, TorrentSession, Domain-сборке или конкретным типам движка; использовать Contracts.
- Не передавать живую изменяемую коллекцию через интерфейс модуля.
- Не помещать правила коллекции, восстановление или управление менеджерами в окна и ViewModel.
- Не создавать второй движок/сборщик ради трея и не останавливать передачу при последней отписке UI.
- Не накапливать неограниченную очередь устаревших обновлений и не оставлять подписки без владельца.
- Не прятать неподдерживаемые данные под нулями или молча повторять команды при восстановлении наблюдения.
- Не обходить граф ссылок через общую сборку, динамический поиск реализации или временное глобальное отключение архитектурных правил.
- Не считать названия архивных workflows, старые счётчики тестов и статусы active/closed доказательством текущей реализации.

Правила проверяются в [Architecture.Tests](../../tests/NiTorrent.Architecture.Tests/ModuleArchitectureTests.cs); конкурентность и работа подписок — отдельными lifecycle-тестами. Подробности и ограничения — [отчёт](../analysis/MODULAR_MONOLITH_IMPLEMENTED_2026-11-27.md).
